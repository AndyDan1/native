# Talking Tom Voice Repeater (Expo + Rive)

Тестове завдання: Реалізувати екран "повторялки" на React Native (Expo) за принципом Talking Tom.

## Вимоги та реалізація
- ✅ **Expo + rive-react-native:** Використано (анімація підключена локально через `assets`).
- ✅ **Автоматичний старт запису:** Запис починається, коли рівень гучності (metering) перевищує `-30dB`.
- ✅ **Автоматична зупинка:** Запис зупиняється рівно через `1 секунду` тиші (guarded via hysteresis: noise < `-40dB`).
- ✅ **Pitch відтворення:** Відтворення записаного голосу через `expo-av` зі збільшеною швидкістю (`rate: 1.5, shouldCorrectPitch: false`), що імітує "муляшний" високий голос як у Тома.
- ✅ **Безперервна логіка:** Додаток постійно моніторить шум, записує та відтворює без жодної кнопки. Rive-персонаж відображає поточний стан через State Machine (Idle -> Hear -> Talk -> Idle).
- ✅ **Без серверів:** Вся обробка звуку відбувається "on-device".

## Архітектурні рішення (Чому так?)

1. **VAD (Voice Activity Detection) через `status.metering` та обрізання тиші:**
   Оскільки `expo-av` не має вбудованої функції видалення тиші, додаток у стані `IDLE` безупинно пише аудіо в буфер, використовуючи його як щуп гучності. Коли ідентифікується "голос" (`metering > -30`), ми запам'ятовуємо точний `status.durationMillis`. Під час відтворення я повертаю позицію старту через `positionMillis: offset`, щоб відкинути весь той шум/тишу, які були до моменту розмови. Це усунуло проблему величезних затримок між записом та відтворенням.

2. **Гістерезис детекції звуку:**
   Щоб персонаж не "блимав" між станом `Hear` і `Check` через мікрофонові стрибки (наприклад, фоновий шум кімнати балансує біля `-35dB`), було введено гістерезис. Запис активується при гучності `> -30dB`, а стан тиші трикутно фіксується лише після падіння `< -40dB`.

3. **`Image.resolveAssetSource` для локального Rive:**
   Щоб уникнути ручного прописування нативних Objective-C/Swift копіювань файла (`resourceName` в Rive), я використаю `Image.resolveAssetSource(require(...)).uri`. Це бере `5628-11215-wave-hear-and-talk.riv` напряму з локального бандлера Metro, дозволяючи йому ідеально завантажуватися через властивість `url={...}` у дев-режимі без зайвої нативної конфігурації.

4. **Безпечне звільнення пам'яті (Memory Leaks / Crashes):**
   Часто `expo-av` видає або зависання `Session activation failed`, або падає з помилкою подвійного `unloadAsync`. Це оброблено за допомогою строгих `try/catch` функцій `safeUnloadRecording` та затримок очищення сесії (`setTimeout 300ms`), щоб OS встигала вивільняти мікрофонні ресурси.

## Запуск проекту

Оскільки Rive використовує нативні C++ модулі, додаток **не запуститься** в класичному Expo Go. Для перевірки необхідно зібрати Development Build:

```bash
npm install
npx expo prebuild --clean
npx expo run:ios
```
